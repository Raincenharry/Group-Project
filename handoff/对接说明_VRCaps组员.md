# 对接说明：给负责 VR-Caps 的组员

你负责从 VR-Caps（Unity）导出两批数据。这份文件说明每批数据交给谁、是什么格式、按什么顺序交付。

整体流程：你在 VR-Caps 里渲染出不同光照下的真实图像；PR-ENDO 组员根据你给的光照参数，用模型生成对应的模拟图像；两组图像都交给 Yutong 比较。

| 数据 | 内容 | 交给谁 |
| --- | --- | --- |
| A. 训练数据 | 一段视频的每一帧：光源在镜头上的图像、深度、相机位姿 | 负责 PR-ENDO 的组员 |
| B1. 光照参数 | 选了哪些帧、每种光照配置的参数、每帧的光源位姿 | PR-ENDO 组员 和 Yutong |
| B2. 多光照图像 | 这些帧在每种光照配置下重新渲染的图像 | 只给 Yutong |

训练数据的格式沿用 PR-ENDO 官方合成数据集 RotateColon 的格式，这样 PR-ENDO 组员改动最少。

## 1. 开始之前，请先回答这几个问题

请把答案同时发给 PR-ENDO 组员和 Yutong：

1. VR-Caps 项目用的是哪个渲染管线：Built-in、URP 还是 HDRP？Unity 版本是多少？
2. 胶囊上默认的光源是点光源还是聚光灯？能不能改成点光源？
3. 组织材质有没有用次表面散射？
4. 相机的视场角和分辨率是多少？图像有没有畸变？
5. 场景有没有真实尺寸？1 个 Unity 单位等于多少毫米？
6. 能不能导出线性的 EXR 图像（渲染到浮点纹理），而不是屏幕截图？

## 2. 分三次交付

不要一次导出全部数据。先交一个很小的包，确认格式没问题，再导出大的。

| 阶段 | 你交付 | 规模 | 你会收到 |
| --- | --- | --- | --- |
| 1 试跑包 | A 和 B 各一小份 | 约 50 张训练帧；2 个主要帧的全部光照配置；5 个标定帧的全部内容 | 两份检查回执，逐项列出通过或不通过 |
| 2 训练数据 | 完整的 A | 整条轨迹 | 训练是否正常，以及几张渲染图 |
| 3 多光照图像 | 完整的 B | 约 1000 张 | 是否收齐、是否有需要重新导出的 |

阶段 1 的回执通过之前，不要开始阶段 2 和 3。

## 3. 所有文件共同遵守的约定

### 坐标系

- **世界坐标系**：右手系。相机位姿和光源位姿用同一个世界坐标系。
- **相机坐标系**：OpenGL / Blender 约定。+X 朝右，+Y 朝上，相机看向 −Z。
- **相机矩阵 `transform_matrix`**：4×4 的相机到世界（c2w）矩阵。前三列依次是相机的右、上、后方向在世界坐标里的单位向量，第四列是相机中心。
- Unity 是左手坐标系，导出时必须转换。相机和光源要用同一个转换。

下文把相机的右、上、前三个方向记为 r、u、f。f 等于 c2w 第三列取反。

### 长度和角度

- 相机位置、深度、光源位置用同一个长度单位。
- 参考距离 d_ref：所有训练帧深度的中位数，由你计算。光源的偏移量用 d_ref 的倍数表示。
- 角度单位是度。yaw 为正表示光束转向相机右侧，pitch 为正表示光束转向相机上方。yaw 和 pitch 都是 0 时，光束方向等于 f。

### 颜色

- **线性图像**：数值和光强成正比，没有经过色调映射。存成 EXR。
- **PNG 图像**：由线性图像转换得到。把数值截断到 0–1，取 1/2.2 次方，存成 8 位。不要用 Unity 的 sRGB 曲线、色调映射或屏幕截图。
- **曝光**：固定，整个数据集用同一个值。选择曝光时，让训练图像里过曝（线性值大于等于 1）的像素少于 1%。

## 4. 文件夹结构

每次交付一个文件夹，命名为 `VRCaps_<场景名>_v<版本号>`，比如 `VRCaps_colon1_v1`。

```
VRCaps_colon1_v1/
├── transforms.json            训练相机                    ┐
├── train_views/0000.png       训练图像                    │ A. 训练数据
├── depth_train/0000.exr       训练深度                    ┘
└── relight/                                               ┐
    ├── export_settings.json   Unity 导出设置              ┐
    ├── transforms_relight.json  多光照帧的相机            │ B1. 光照参数
    ├── lights.json            光照配置和每帧的光源位姿    ┘
    ├── depth/0100.exr         多光照帧的深度              ┐ B2. 多光照图像
    └── gt/<配置编号>/<noshadow 或 shadow>/0100.exr        ┘
```

帧号统一补零到 4 位。

交付时分成两份：

| 给谁 | 内容 |
| --- | --- |
| Yutong | 整个文件夹 |
| PR-ENDO 组员 | 整个文件夹去掉 `relight/gt/` 和 `relight/depth/`。他只需要训练数据和光照参数，不需要看到多光照图像 |

## 5. A. 训练数据

### 5.1 用哪些帧

视频的所有帧都是训练帧，不需要另外留出测试帧。B 里用到的帧也是从这些训练帧里选的。

### 5.2 `transforms.json`

```json
{
  "camera_angle_x": 0.733,
  "frames": [
    {"file_path": "0", "transform_matrix": [[...], [...], [...], [0, 0, 0, 1]]}
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `camera_angle_x` | 水平视场角，弧度 |
| `frames[].file_path` | 帧号，不补零。对应的文件名是补零到 4 位的帧号，比如 `"7"` 对应 `0007.png` |
| `frames[].transform_matrix` | 4×4 的相机到世界矩阵，约定见第 3 节 |

相机要求：无畸变，像素是正方形，主点在图像中心。做不到的话，另外给出 `fl_x`、`fl_y`、`cx`、`cy`（像素单位），并提前告诉 PR-ENDO 组员。

### 5.3 图像和深度

| 文件 | 格式 | 内容 |
| --- | --- | --- |
| `train_views/<帧号>.png` | 8 位 RGB PNG | 训练图像，由线性图像按第 3 节的方法转换 |
| `depth_train/<帧号>.exr` | EXR，单通道浮点 | 线性的 z 深度（沿光轴的距离），单位和相机位置一致；每张训练图像都要有 |

Unity 深度缓冲默认是非线性的 0–1 值，不能直接存，要先转换成线性的视空间深度。EXR 里深度通道的名字请记在 `relight/export_settings.json` 里。

### 5.4 光源

所有训练帧的光源都是基准光源：放在相机中心的点光源，白色，固定强度。不要用聚光灯。

## 6. B. 光照参数和多光照图像

### 6.1 用哪些帧

这些帧直接从训练视频里选，帧号和相机位姿与 `transforms.json` 里的同一帧完全相同。把它们再写一份到 `relight/transforms_relight.json`，格式和 `transforms.json` 相同，每帧多一个 `split` 字段。

| 帧组 | 数量 | 选法 | `split` |
| --- | --- | --- | --- |
| 主要帧 | 30 | 沿轨迹等间隔选取 | `test` |
| 序列帧 | 2 段 × 10 帧 | 每段取轨迹上连续 20 帧的范围，隔一帧取一帧 | `test` |
| 标定帧 | 5 | 沿轨迹等间隔选取，避开主要帧 | `calib` |

### 6.2 渲染哪些光照配置

基准光源是训练时用的那个：相机中心的点光源，白色，固定强度。表里没有提到的量都保持基准值。

| 级别 | 改什么 | 光源类型 | 取值 | 配置编号 |
| --- | --- | --- | --- | --- |
| L0 | 不改 | 点光源 | 基准光源 | `L0` |
| L1 | 光强 | 点光源 | 0.5 倍，2.0 倍 | `L1_s0.5`，`L1_s2.0` |
| L2 | 光束方向，光源仍在相机中心 | 聚光灯 | 朝前；yaw = ±10、±20、±40；pitch = ±20 | `L2_fwd`，`L2_yaw+10` … `L2_pitch-20` |
| L3 | 光源位置 | 点光源 | 向右 0.10、0.25、0.50、1.00；向上 0.25、0.50；向前 +0.25、向后 −0.25 | `L3_r0.10` … `L3_f-0.25` |
| L4 | 光的颜色 | 点光源 | (1, 0.5, 0.5)，(0.5, 1, 0.5)，(0.5, 0.5, 1) | `L4_red`，`L4_green`，`L4_blue` |
| L5 | 光源固定在场景里，不跟随相机 | 点光源 | 固定在该段第一帧的相机中心 | `L5_seg1`，`L5_seg2` |

说明：

- L3 的数值是 d_ref 的倍数。光源的世界坐标 = 相机中心 + d_ref ×（向右分量 × r + 向上分量 × u + 向前分量 × f）。
- L2 的聚光灯：外锥半角默认 30°，内锥半角取 Unity 允许的最小值。所有 L2 配置用同一组锥角。如果相机视场角和这个锥角差得很多，先和 Yutong 商量。
- L2 的光束方向 = cos(pitch) ×（cos(yaw) × f + sin(yaw) × r）+ sin(pitch) × u。
- L4 的三个数是红、绿、蓝三个通道相对基准光源的倍数。
- L3 的光源必须在肠腔内。如果光源到最近表面的距离小于 0.05 × d_ref，或者相机中心到光源的连线穿过了表面，这一帧在该配置下标记为无效，可以不渲染。

### 6.3 每种配置渲染几个版本

L3 和 L5 的光源离开了相机中心，会产生看得见的阴影，所以要渲染两个版本：关闭阴影（`noshadow`）和打开阴影（`shadow`）。其他级别只要 `noshadow`。

| 帧组 | 配置 | `noshadow` | `shadow` | 图像数 |
| --- | --- | --- | --- | --- |
| 主要帧（30） | L0、L1、L2、L4（15 种） | 要 | 不要 | 450 |
| 主要帧（30） | L3（8 种） | 要 | 要 | 480 |
| 序列帧（20） | L0 | 要 | 不要 | 20 |
| 序列帧（20） | L5 | 要 | 要 | 40 |
| 标定帧（5） | `L0`、`L2_fwd`、`L2_yaw+20` | 要 | 不要 | 15 |
| 标定帧（5） | `L3_r0.25` | 要 | 要 | 10 |

合计 1015 张。

### 6.4 文件格式

| 文件 | 格式 | 内容 |
| --- | --- | --- |
| `gt/<配置编号>/<版本>/<帧号>.exr` | EXR，RGB 三通道，半精度或单精度浮点 | 线性图像，分辨率和训练图像相同 |
| `depth/<帧号>.exr` | EXR，单通道 | z 深度，和训练深度同一约定；没有表面的像素填 0 |

### 6.5 `lights.json`

```json
{
  "mm_per_unit": null,
  "d_ref": 1.06,
  "base_light": {"type": "point", "intensity": 5.0, "color": [1, 1, 1]},
  "configs": [
    {
      "id": "L3_r0.25", "level": "L3", "type": "point",
      "intensity_scale": 1.0, "color_scale": [1, 1, 1],
      "offset_dref": [0.25, 0, 0], "yaw_deg": 0, "pitch_deg": 0,
      "spot_inner_deg": null, "spot_outer_deg": null,
      "world_fixed": false, "variants": ["noshadow", "shadow"]
    }
  ],
  "frames": [
    {
      "config": "L3_r0.25", "frame": "0100",
      "light_pos_world": [-0.19, -1.62, 0.23],
      "light_dir_world": [0.10, 0.99, 0.08],
      "valid": true
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `mm_per_unit` | 1 个长度单位等于多少毫米；不知道就填 null |
| `d_ref` | 参考距离 |
| `base_light.intensity` | 基准光强，Unity 里的数值原样记录 |
| `configs[].id`，`level` | 配置编号和级别，和 6.2 一致 |
| `configs[].type` | `point` 或 `spot` |
| `configs[].intensity_scale` | 光强倍数 |
| `configs[].color_scale` | 红、绿、蓝三个通道的倍数 |
| `configs[].offset_dref` | 向右、向上、向前的偏移，d_ref 的倍数；L5 填 null |
| `configs[].yaw_deg`，`pitch_deg` | 光束的 yaw 和 pitch |
| `configs[].spot_inner_deg`，`spot_outer_deg` | 聚光灯内、外锥的半角；点光源填 null |
| `configs[].world_fixed` | 光源是否固定在场景里；只有 L5 为 true |
| `configs[].variants` | 这个配置渲染了哪些版本 |
| `frames[].config`，`frame` | 配置编号和 4 位帧号，对应 `gt/<config>/<版本>/<frame>.exr` |
| `frames[].light_pos_world` | 这一帧里光源的世界坐标 |
| `frames[].light_dir_world` | 这一帧里光束方向的单位向量；点光源填相机的前方向 |
| `frames[].valid` | 光源是否在肠腔内 |

`frames` 里每个（配置，帧）一条。

### 6.6 `export_settings.json`

如实记录第 7 节每一项的实际取值，至少包括：Unity 版本、渲染管线、颜色空间、曝光值、光源类型和衰减设置、光源作用范围、阴影设置、环境光和间接光设置、分辨率、视场角。

## 7. Unity 设置

A 和 B 都用这套设置。

| 设置 | 要求 |
| --- | --- |
| 颜色空间 | 项目设为 Linear |
| 色调映射 | 关闭 |
| 曝光 | 固定曝光，关闭自动曝光 |
| 其他后处理 | 全部关闭：泛光、暗角、色彩校正、胶片颗粒、景深、运动模糊 |
| 抗锯齿 | 可以开，所有渲染保持一致 |
| 光源数量 | 每次渲染只有一个光源 |
| 环境光、天空盒 | 强度设为 0 |
| 间接光 | 关闭全局光照、反射探针、屏幕空间反射 |
| 距离衰减 | 平方反比 |
| 光源作用范围（Range） | 至少 20 × d_ref |
| 光源大小 | 半径为 0 |
| 聚光灯 Cookie | 不使用 |
| 阴影 | `noshadow`：光源的 Shadow Type 设为 No Shadows；`shadow`：硬阴影，阴影分辨率取最高 |
| 材质 | 所有渲染用同一套材质 |
| 图像输出 | 渲染到浮点纹理，存成 EXR |
| 深度输出 | 线性的视空间 z 深度 |

## 8. 交付前的自检

前六项用几行 Python 就能验证。

- [ ] **线性导出**：同一帧的 `L1_s2.0` 图像等于 `L0` 图像的 2 倍，`L1_s0.5` 等于 0.5 倍，逐像素误差在 1% 以内。不满足说明有自动曝光、色调映射或环境光没关掉。
- [ ] **颜色倍数**：同一帧的 `L4_red` 图像，红通道等于 `L0` 的红通道，绿、蓝通道等于 `L0` 的 0.5 倍。
- [ ] **编码一致**：把一张训练帧的线性图像按第 3 节的方法转换后，和 `train_views/` 里对应的 PNG 逐像素相差不超过 1/255。
- [ ] **过曝比例**：训练图像中线性值大于等于 1 的像素少于 1%。
- [ ] **阴影开关**：L3 的 `shadow` 版本在任何像素都不比 `noshadow` 版本亮。
- [ ] **光源位姿**：L3 的每一帧，`light_pos_world` 到相机中心的距离等于偏移量的长度乘以 d_ref；L0、L1、L2、L4 的每一帧，`light_pos_world` 等于相机中心。
- [ ] **位姿和深度**：取相隔较远的两帧，把深度图按相机位姿反投影到世界坐标，两帧看到的同一块表面应该重合。不重合说明相机位姿或深度的约定有错。PR-ENDO 组员在阶段 1 也会做这项检查。
- [ ] **帧一致**：`transforms_relight.json` 里的每一帧都能在 `transforms.json` 里找到，帧号和相机矩阵完全相同。
- [ ] **文件齐全**：`lights.json` 的 `frames` 里每个 `valid` 为 true 的条目，在其配置的每个版本下都有对应的 EXR。
- [ ] **设置记录**：`export_settings.json` 填写完整。

## 9. 版本规则

- 任何一次重新导出都换一个新的版本号，不要覆盖旧文件夹。
- 如果只改了 `relight/`，训练数据没变，请在交付时说明，PR-ENDO 组员就不用重新训练。

如果某个要求在 VR-Caps 里做不到，请尽早说，不要自己换一种做法。
