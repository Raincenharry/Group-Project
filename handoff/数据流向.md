# 数据流向

VR-Caps 组员渲染不同光照下的真实图像，PR-ENDO 组员按同样的光照参数生成模拟图像，两组图像都交给 Yutong 比较。

## 1. 谁把什么交给谁

```
                    ┌──────────────────┐
                    │   VR-Caps 组员   │
                    └──────────────────┘
                      │       │       │
        ② 训练数据    │       │       │  ④ 真实的多光照图像
        ③ 光照参数    │       │       │  ③ 光照参数
                      ▼       │       ▼
        ┌──────────────────┐  │  ┌──────────────────┐
        │  PR-ENDO 组员    │  │  │      Yutong      │
        │  训练模型        │  │  │  比较两组图像    │
        │  生成模拟图像    │──┼─►│                  │
        └──────────────────┘  │  └──────────────────┘
               ⑦ 模拟的多光照图像

  ① 六个问题的回答：VR-Caps 组员 → 另外两人
  ⑤ 训练数据的检查回执：PR-ENDO 组员 → VR-Caps 组员
  ⑥ 聚光衰减指数 n：Yutong → PR-ENDO 组员
  ⑧ 图像的检查回执：Yutong → VR-Caps 组员 和 PR-ENDO 组员
```

| 编号 | 内容 | 从 | 到 | 定义在哪 |
| --- | --- | --- | --- | --- |
| ① | 渲染管线、光源类型、材质、视场角、尺度、能否导出 EXR | VR-Caps 组员 | 另外两人 | VR-Caps 说明第 1 节 |
| ② | 视频每一帧的图像、深度、相机位姿 | VR-Caps 组员 | PR-ENDO 组员 | VR-Caps 说明第 5 节 |
| ③ | 选了哪些帧、25 种光照配置的参数、每帧的光源位姿 | VR-Caps 组员 | 另外两人 | VR-Caps 说明第 6 节 |
| ④ | 选出的帧在每种光照配置下，Unity 渲染的真实图像 | VR-Caps 组员 | Yutong | VR-Caps 说明第 6 节 |
| ⑤ | 训练数据逐项通过或不通过 | PR-ENDO 组员 | VR-Caps 组员 | PR-ENDO 说明第 5 节 |
| ⑥ | 一个数，用于聚光灯配置 | Yutong | PR-ENDO 组员 | PR-ENDO 说明第 4.3 节 |
| ⑦ | 同样的帧和光照配置下，PR-ENDO 生成的模拟图像，加一份记录 | PR-ENDO 组员 | Yutong | PR-ENDO 说明第 4.4 节 |
| ⑧ | 真实图像和模拟图像各自有没有问题 | Yutong | 另外两人 | 无固定格式 |

②、③、④ 在同一个文件夹 `VRCaps_<场景名>_v<版本号>/` 里。交给 Yutong 的是整个文件夹；交给 PR-ENDO 组员的那份去掉真实图像（`relight/gt/` 和 `relight/depth/`）。

④ 和 ⑦ 靠配置编号和帧号一一对应，这两个名字都来自 ③ 里的 `lights.json`。

## 2. 先后顺序

| 阶段 | VR-Caps 组员 | PR-ENDO 组员 | Yutong |
| --- | --- | --- | --- |
| 0 | 回答六个问题 ① | 确认光源能改成点光源、图像无畸变 | 确认聚光灯锥角等设置 |
| 1 试跑 | 交小份的 ②③④：约 50 帧训练数据，2 个主要帧和 5 个标定帧 | 检查 ②，短训练，发回执 ⑤；生成试跑的 ⑦ | 检查 ④；算出 n 交给 PR-ENDO 组员 ⑥；检查试跑的 ⑦，发回执 ⑧ |
| 2 训练 | 交完整的 ② | 完整训练 | 无 |
| 3 多光照 | 交完整的 ③④ | 生成全部 ⑦ | 比较 ④ 和 ⑦ |

阶段 1 的回执 ⑤ 和 ⑧ 都通过之后，VR-Caps 组员才开始导出完整数据。

## 3. 谁在等谁

- PR-ENDO 组员等 VR-Caps 组员的 ② 才能训练，等 ③ 才能生成图像，等 Yutong 的 ⑥ 才能生成聚光灯配置的图像。
- Yutong 等 ④ 和 ⑦，两样都到了才能比较。
- VR-Caps 组员在阶段 1 之后等 ⑤ 和 ⑧。

阶段 2 和阶段 3 的导出互不依赖。阶段 1 通过后，VR-Caps 组员可以两样同时导出，不用等训练结束。

## 4. 重新导出时

- 每次重新导出或重新生成都换新的版本号或运行编号，不覆盖旧的。
- ② 变了：PR-ENDO 组员重新训练，并重新生成 ⑦。
- 只有 ③④ 变了：不用重新训练，PR-ENDO 组员按新的 ③ 重新生成 ⑦。
- ⑦ 的记录里写明用的是哪个数据版本。Yutong 比较时，④ 和 ⑦ 必须来自同一个版本。
